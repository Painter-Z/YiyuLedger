# 小米 14 金额输入键盘反馈

日期：2026-10-12。状态：未定位到确定原因，保留 0.6.1，不发布推测性修复。

## 用户信息与视频

一位用户反馈手动记账点击金额后，键盘弹出偏慢；最初版本为 0.5.0，更新到 0.6.1 后仍觉得慢一下。型号由用户确认为小米 14；Android 16 和百度输入法小米版均为转述中的估计，尚未读取真机验证。其他安卓用户据反馈没有复现。

查看本机桌面的 `反馈.mp4`，解码全部 77 帧，画面为 1200×2670，约 24 帧/秒。金额框约在 1.490 秒出现焦点边框与光标，约在 1.614 秒出现键盘顶部；此后键盘与底部保存按钮逐步上移，约在 2.8 秒稳定。保存按钮的纵坐标记录于 `artifacts/keyboard-feedback/video-save-positions.json`，逐帧联系表为同目录 `transition-all-frames.jpg`。

这段录像呈现了较长的升起动画，不能据此认定点击事件等待了一秒。录像没有触摸标记，不能测量真实点击至焦点出现的延迟；录像帧率也不能用于判断手机渲染帧率。系统动画、输入法与应用窗口避让各自的耗时尚未分离，不能直接归因于用户手机或百度输入法。

## 代码核对

- `newManual()` 创建本地编辑状态，点击金额框仅请求输入焦点；没有在该点击路径调用云识别、读写账本或等待业务结果。
- 0.5.0 使用默认 Dialog 窗口适配，加上 `imePadding()` 与 `navigationBarsPadding()`；0.6.1 改为窗口内统一处理 `safeDrawing`，并根据可用空间切换紧凑布局。两版均保留 `adjustResize` 和数字金额输入类型。
- 分类推荐未缓存、0.6.1 的 `BoxWithConstraints` 随可用高度变化可能重新组合，是进一步性能分析的候选点。没有证据证明它们造成此台手机的反馈，本轮没有把候选点当成根因修改。

## Android 16 对照

在同一 `Yiyu_API36` 开发模拟器运行两版原始安装包，各打开 8 次空账本的手动金额键盘，均通过；没有创建或保存账单，没有联网，也没有操作用户真机。两版 APK 的摘要在 `artifacts/keyboard-feedback/comparison.json`。

| 安装版本 | 成功次数 | 第 2–8 次 IME 窗口可见时间中位数 | 第 2–8 次范围 |
| --- | --- | --- | --- |
| 0.5.0 | 8 / 8 | 396 ms | 382–426 ms |
| 0.6.1 | 8 / 8 | 421 ms | 374–443 ms |

以上数字包含 UIAutomator 注入及无障碍窗口轮询开销，**不是手机触摸响应基准，也不是动画完成时间**。两版结果重叠，没有测到版本间的秒级等待差异。模拟器使用 Gboard 和软件渲染，没有小米系统及百度输入法，无法据此宣称该反馈已复现、已解决或一定由手机引起。原始 Native FrameMetrics 留存供后续对照，不当作真机帧率。

探针为 `android/app/src/androidTest/java/com/yiyu/ledger/KeyboardOpeningProbeTest.kt`，不依赖业务模型，可用同一测试 APK 对照旧安装包。只允许在开发模拟器执行；独立于默认设备回归，需显式指定测试类。日志与原始 JSON 位于 `artifacts/keyboard-feedback/api36-<版本>-probe.*`。0.6.1 的截图和界面树亦在同目录。

## 当前处理

遵循用户“暂时找不到原因就先不管”的指示：保留已交付的 0.6.1，应用生产代码、数据库、密钥存储及鸿蒙端不变。后续如反馈增多或有可用真机，再比较同一手机不同输入法、系统动画设置、金额与名称输入框，以及主线程追踪；目前不要求用户逐项排查或改变系统设置。
