# 朋友试用与发布准备

最新个人试用包为安卓0.7.0和鸿蒙0.7.0。两端均优化口语金额、多笔账单的原话对应及逐笔确认进度，见[鸿蒙识别修复](HARMONY-0.7.0-RECOGNITION.md)和[安卓同步说明](ANDROID-0.7.0.md)。两端支持近三天账单、居中日历、全天支出、历史搜索及结果末尾“返回”，见[日期与搜索](HARMONY-LEDGER-BROWSING.md)及[安卓0.6.2](ANDROID-0.6.2.md)。两端原有左滑删除和月预算规则一致，见[功能说明](SWIPE-AND-MONTHLY-BUDGET.md)。鸿蒙覆盖安装到Pura80Pro；安卓本轮使用开发模拟器验证。此前安卓0.5.0在Xiaomi14上由用户确认拔掉USB后识别、保存及账单显示正常；另有朋友已覆盖至0.6.1。朋友两种系统分别使用对应原生包。

## 这版保留什么

| 功能 | 处理 |
| --- | --- |
| 语音、手动、文字记账 | 保留；智能记账只需添加个人百炼 API Key |
| 自建服务、地址、连接口令、独立测试按钮 | 从客户端删除 |
| 录音草稿列表 | 设置中移除；有未完成记录才在首页出现继续入口 |
| 非记账内容、无有效转写、上滑取消 | 删除对应录音，不生成账单 |
| 已识别但未全部确认 | 删除录音，保存待确认账单和确认进度 |
| 确认页分类与保存 | 默认选中项＋最多两个推荐项＋更多；支持自定义分类；保存区固定在底部 |
| 网络失败、后台中断 | 录音暂存24小时，支持重试或主动移除；下次启动/回前台清理到期录音 |
| CSV导出、JSON备份恢复 | JSON v3包含自定义分类和月预算；兼容v1/v2且忽略其删除记录 |
| 删除账单 | 账单左滑展开红色按钮；确认后实际删除，同步刷新统计、预算进度及相关缓存；用户已导出文件保留 |
| 月预算 | 统计页设置；显示剩余或超支金额，额度沿用后续月份；本地保存，可离线使用 |
| 会员入口、支付、登录 | 本版不添加占位入口，待服务可用后接入 |

## 给朋友安装

安卓朋友使用`artifacts/YiyuLedger-0.7.0-android-debug.apk`。这是标准APK，最低Android8.0，包含arm64-v8a、armeabi-v7a、x86、x86_64；不依赖Google Play服务，不需要电脑、USB或设备专属签名。朋友在手机文件管理器打开APK，按系统提示允许安装；首次录音授予麦克风权限，并在设置填写自己的百炼API Key。没有Key也能手动记账。更新时直接覆盖安装，保留原账本与预算；不要先卸载。

当前`YiyuLedger-0.7.0-signed.hap`是当前手机的调试签名包，不能承诺发送给任意手机即可安装。华为调试Profile关联注册设备，变更设备后需要更新Profile并重新签名，见[申请调试Profile](https://developer.huawei.com/consumer/cn/doc/doccenter-getting-started/agc-help-debug-profile-0000002248181278)。

少量原生鸿蒙朋友可先按官方流程注册测试设备，再生成包含这些设备的调试签名包。人数增加后评估 AppGallery Connect 的官方测试分发；[AppTest应用介绍](https://consumer.huawei.com/cn/support/content/zh-cn16046463/)包含面向受邀用户的测试方式。具体账号资格、审核和软件包要求以控制台为准。本次未代替用户提交分发申请、发送邀请或公开发布。

朋友各自添加个人百炼密钥，安装包不携带开发者或其他用户的密钥。试用说明要覆盖密钥获取、联网需求、识别用量和本地备份，避免把开发环境配置当成用户操作。

安卓已提供独立工程及个人测试APK，当前HAP继续用于鸿蒙。安卓沿用同一套页面结构、人民币整数分规则、百炼提取协议、确认流程及备份格式；录音、系统密钥、本地数据库和文件选择器使用Android原生接口。两端共用合成样例验证了备份格式，实际文件选择器迁移仍需真机验收，再扩大试用。

小米澎湃OS的Android路线、两端协议及开发顺序见 [安卓移植准备](ANDROID-PORT-PLAN.md)，实际环境及安装步骤见 [安卓说明](ANDROID-QUICKSTART.md)。当前APK为调试签名，正式商店发布前需建立长期发布签名和审核资料。

## 先验证再扩大范围

先收集少量朋友的常用语料，逐条记录原话、转写、名称、金额、分类、日期及是否需要修正，覆盖餐饮、交通、收入、多笔、口误和非记账闲聊。金额和类型错误优先处理。

在扩大邀请前完成拒绝麦克风权限、锁屏/来电、移动网络切换、失败重试、部分确认后重启恢复，以及真机 CSV/JSON 导出恢复。记录机型、鸿蒙/API版本或安卓版本，保持可追踪的版本号，不用单次演示成功代替完整验收。

0.4.0已在当前手机实测系统特大字体、大显示缩放及键盘避让。其他屏宽、横屏、折叠态和鸿蒙5仍需要代表性设备验证；不能把按窗口宽度自适应等同于所有机型验收通过。

## 后续会员服务

会员阶段的目标是用户开通后直接记账，客户端自动连接运营服务。运营方百炼密钥留在后端；客户端使用用户身份凭据，不能把共享 API Key 放入安装包。

落地顺序：稳定的 HTTPS/WSS 后端 → 用户身份和权益 → 按用户的调用配额与成本统计 → 支付及服务端验签/权益同步 → 会员入口。账本继续本地保存，识别服务只处理当前请求；是否提供账本云同步另行设计。现有 `backend/` 只是识别中转原型，尚未实现上述会员能力。

正式上架阶段再完善隐私政策、用户协议、应用介绍与截图、发布签名及商店审核资料；具体平台要求以提交时官方控制台为准。
