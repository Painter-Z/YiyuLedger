# 鸿蒙0.7.0：口语金额与多笔账单对应

2026-10-18，版本0.7.0 / code1000011。仅修改鸿蒙；安卓0.6.3、共享数据格式和后端原型保持原样。

## 行为

- “十一块八毛九”“11块8毛9”“十一元八角九”均按11.89元解析；“两块五”按2.50元，“八毛九”按0.89元。金额用整数分校验，不通过浮点加减生成账本金额。
- 明确零角、零分占位及中英文数字混写可解析；“十一二块”“一百二”“两千五”等含糊或省略表达保持待核对。不能从长金额中截取较短片段，也不能将负金额去掉负号后记成正数。
- 每笔云端提案带自己的连续原话和名称引用。名称、金额须来自对应片段，不能借用其他交易的内容；模型顺序错误时按原话位置恢复顺序。
- 如果模型只把名称复制错了，而本笔名称引用明确，使用该引用校正名称并提示确认。若连名称引用也来自上一笔，则留空名称、触发复核，不能默默沿用旧名称。
- 若模型为多笔都引用了整段文字，在各自引用内部按名称与金额的字面位置收紧；只有得到互不重叠的片段才接受。真实的同名、同价交易不会因重复名称或金额而合并。不能安全定位时保留待核对。
- 正常结果只调用一次Qwen。遇到结构、来源或字段不一致，最多追加一次云端复核；失败、无改善或删除已有提案的复核结果不会覆盖原始待确认内容。明确付款却返回空结果也可复核一次。
- 独立交易后的汇总不能重复入账；多件商品只付一次合计时保留一笔合并付款，不编造单项金额。没有明确金额时留空等待补填。
- 确认页显示当前这笔原话；多笔时显示“第X笔 / 共Y笔”。分类推荐也优先使用当前片段，减少其他账单对当前推荐的影响。

报告中的原话“今天我吃了保障餐，花了八块。又喝了一碗粥，花了两块五”对应“保障餐8.00元”和“粥2.50元”。两次确实说了保障餐时仍保留两笔。

## 数据与兼容

账本、CSV及JSON v3备份格式不变。原话引用仅属于未确认提案，不写入已保存账目；保存一笔后，与该笔相关的提案、原话及完整转写一并从缓存裁剪，剩余未确认提案保留自己的片段。旧版没有片段字段的未完成记录继续可用，无需重新识别或配置密钥。

语音模型仍为`fun-asr-realtime`，提取仍为`qwen-plus`；本轮没有训练模型或更换服务商，也没有新增热词词表。修复重点是已复现的金额规则和转写后的账单对应；不能据此承诺所有口音、噪音或同音词均已解决。复核只处理文本提案，不能恢复已被语音服务听错的原始发音。

## 验证

- 78项领域、存储及识别测试通过，其中新增22项识别与缓存检查，覆盖用户例子、同名/同价重复、错配、原文改写或重叠、截断金额、负数、口头更正、外币隔离、复核次数及失败保留。
- 10组真实百炼文本接口样例全部通过；最后一轮均只调用一次Qwen。合并付款、遗漏金额、非记账内容及合计不重复包含在内。
- 两段16kHz单声道合成语音经真实Fun-ASR与当前鸿蒙提取流程，分别得到“保障餐8元＋粥2.5元”和“牛肉面11.89元”。这是合成语音链路验证，不是用户实际口音和噪音环境验证。
- ArkTS编译、签名及Pura80Pro覆盖安装通过。真机文字输入验证双笔确认进度、第一笔对应原话和11.89元金额；未点击保存，也未创建、修改或删除测试账单。
- 本轮升级前后账单、统计和预算一致；未改动真实账单。
